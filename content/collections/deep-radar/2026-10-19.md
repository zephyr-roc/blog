## 01 · rustc DST：把递归布局计算压缩成常数次 IR

**原文与日期：** Josh Liebow-Feeser，2026-10-18 09:57（中原标准时间）；[Rust PR #164492](https://github.com/rust-lang/rust/pull/164492)、[最新源码 diff](https://github.com/rust-lang/rust/commit/499b59f84965a756bca413800eefcb3bb3644d27) 和 [rustc-perf 对比](https://perf.rust-lang.org/compare.html?start=02fb0a16311c3411fa373627706da085cd8fbd3c&end=dfc3d41ae3f9d6fd27dadc3fff8e6d733229b369&stat=instructions:u)。PR 明确披露由 AI agent 代表作者生成，当前仍是 Draft，适合审阅思路与证据，不应视为已合并结论。

**为什么值得读：** 旧的 `size_and_align_of_dst` 每穿过一层 struct/tuple 都同时递归求 size 与 align，即使调用者只需要其中一个；`Layout::for_value_raw` 连续查询二者时还会重复加载 vtable 并重复舍入。新方案不是简单缓存，而是先用布局代数在编译期压缩整个 wrapper chain，再针对 slice/str 尾部与 `dyn Trait` 尾部分别生成最短 IR。这是“把领域不变量编码进代码生成器”的高密度案例。

**核心技术结论：** 补丁拆出 `size_of_dst`、`align_of_dst` 与 `dst_field_offset`，并同时实现于 LLVM 和 Cranelift 后端。slice-tailed DST 被折叠为 `outer_offset + align_to(base + offset, align)`：运行时至多保留一次乘法、一次掩码前加法、一次 `and`，只有外层 packed 布局确实需要时才追加一次掩码后加法。`dyn Trait` 路径跳过 `offset == 0 && align == 1` 的 `ManuallyDrop`、`UnsafeCell` 等空操作 wrapper，合并相邻兼容步骤，并只在必要时加载 `vtable.align`。MIR `InstSimplify` 还把 `str`、单字段 wrapper 及一元 tuple 的 `align_of_val` 折叠为静态元素对齐。

```rust
// 嵌套 slice DST 的目标形态：一次 add + 一次 mask
let unaligned = len + 21;
let size = unaligned & -8;

// dyn Trait wrapper：从最内层向外流式折叠
if cur.offset == 0 && cur.align == 1 {
    continue;
}
```

**最有价值的实验、源码与 benchmark 细节：** codegen 测试把四层 `Level3(u64, Level2(...[u8]))` 的结果固定为 `add nuw i64 %len, 21` 后接 `and ..., -8`，而 `ManuallyDrop<dyn Trait>` 的 `size_of_val` 只剩一次 vtable size load。作者的定向 `-O3` 基准中，零偏移、align(1) 的 `dyn Trait` wrapper 加速 2.18 倍，`Layout::for_value::<Path>` 加速 1.50 倍。官方 rustc-perf 的可靠指令数指标只有 1 个 primary 样本改善 0.4%，无指令回退；secondary 最大 RSS 两个样本平均改善 4.2%，bootstrap `489.750 → 488.876 秒`（-0.18%）。负向结果不能省略：cycles 有 1 个 primary 样本回退 2.5%，2 个 secondary 样本平均回退 5.5%（+2.2% 至 +8.7%）；linked binary 中也有 1 个样本增大 0.6%。评审还发现早期 `nuw nsw` 可能让 LLVM 生成很大的 `and` immediate，最新版本改为掩码前只保留 `nuw`，以维持 x86-64 的紧凑 `andq $-8` 编码。

**适合的工程师背景：** 熟悉 Rust DST/vtable、LLVM IR、布局与对齐规则，或正在维护编译器后端、allocator/deallocation 热路径的工程师。

**预计阅读收益：** 约 60–90 分钟；能学会将递归布局公式化简为常数次运行时运算、区分静态与动态对齐，并理解 `nuw`/`nsw` 元数据如何反过来影响指令选择。

## 02 · GPU 浮点原子：CAS 回退为什么会输给原生 `atomic fadd`

**原文与日期：** yunz-qiao，2026-10-18 10:25（中原标准时间）；[Rust issue #164493](https://github.com/rust-lang/rust/issues/164493)、[LLVM `atomicrmw fadd` 语义](https://llvm.org/docs/LangRef.html#atomicrmw-instruction) 与 issue 中可直接复现的 Rust、AMDGPU inline asm、LLVM intrinsic、HIP C++ 对照代码。

**为什么值得读：** 这不是抽象的 API 偏好，而是从 `std::offload` 的 LLM attention reduction 出发，把“用整数原子位模式做 CAS 循环即可”的常见回答放到真实 GPU contention 下检验。材料同时覆盖端到端 token/s、微型高争用 kernel、LLVM intrinsic 与硬件指令，足以把 API 缺口和性能后果连接起来。

**核心技术结论：** `AtomicU32::compare_exchange_weak` 能在语义上实现浮点加法，但每次失败都必须重新读取、把 bit pattern 转回 `f32`、相加并重试；线程越多、热点越集中，失败重试越严重。原生路径直接发出 AMDGPU `global_atomic_add_f32`，或调用 `llvm.amdgcn.flat.atomic.fadd.f32.p0`；HIP 对照则使用 `atomicAdd(p, 1.0f)`。因此工程问题不是“能否表达”，而是 Rust 是否能稳定、跨后端地暴露与 LLVM `atomicrmw fadd` 对应的能力，并清楚定义 IEEE 浮点、NaN 与内存序语义。

```rust
while let Err(seen) = a.compare_exchange_weak(
    cur,
    (f32::from_bits(cur) + x).to_bits(),
    Relaxed,
    Relaxed,
) {
    cur = seen;
}

core::arch::asm!(
    "global_atomic_add_f32 {off}, {v}, {base} scope:SCOPE_DEV",
    off = in(vgpr32) 0u32,
    v = in(vgpr32) x,
    base = in(sgpr64) p as u64,
);
```

**最有价值的实验、源码与 benchmark 细节：** 在 RX 9070 XT（gfx1201）上，GPT-2 在 context 1,023 的 decode 吞吐从未拆分 attention 的 171 token/s 提升到原生浮点原子路径的 245 token/s，提升 43.27%；CAS-loop 路径为 233 token/s，原生指令相对它再高 5.15%。更能揭示机制的是高 contention 数据：没有 inline asm 时，Rust 在 context 1,024 的 attention kernel 约慢 3.8 倍；对单个共享 float 的争用超过 300 倍；调优后的 vocabulary softmax sum 慢 3–5 倍；一线程一元素的 launch 最差达到 400 倍。issue 给出完整 `no_std` kernel、`-Ctarget-cpu=gfx1201` 构建命令与 HIP `-O3 --offload-arch=gfx1201` 对照，避免只凭端到端数字猜原因。

**适合的工程师背景：** 熟悉 Rust atomics、LLVM/AMDGPU、GPU reduction，或正在用 Rust 实现 attention、softmax、图计算等高争用归约 kernel 的工程师。

**预计阅读收益：** 约 35–50 分钟；能掌握 CAS-loop 在 GPU 上的失败放大机制、如何设计原生指令/LLVM intrinsic/HIP 三方对照实验，以及评审浮点原子 API 时必须追问的数值与内存模型边界。

## 本期结论

两项材料都把“抽象等价”与“机器成本”分开验证：DST 优化利用布局代数把 O(n) wrapper 处理压成常数次 IR，却仍需面对 cycles 噪声与指令选择细节；浮点 CAS 在语义上可用，但热点争用下与原生原子指令存在 5% 到数百倍不等的差距。可迁移的方法是先从不变量推导最短表示，再用定向微基准、端到端工作负载和负向指标共同约束结论。
